Camera lock during the climb -- removed after v31.
====================================================

This worked. It was taken out because camera movement during a climb belongs in
the animation, not in a script: authored against the hands, in step with them
for free, and without any of the guessing below.

Kept because it cost several rounds of tuning to get right, and because the
facts it established -- the sign of the pitch, which control flag is looking,
that SetAngle X moves the first person view at all -- are worth more than the
code. Those are written up in STATE.md under Hard-won facts.

If it is ever wanted again, this is the last working state, out of
scripts-game/udf/MainLoop.gek and scripts-game/ln_Mantle.txt.

What it did
-----------

For the first `*_Mantle_CamLock` (0.8) of the climb the looking control was
taken away and the angles driven directly. Yaw was frozen at the value it had
when the climb started -- no arithmetic needed, because the obstacle was found
by casting a ray along the way the player was already facing, so that heading is
already aimed at it. Pitch ran an eased look-at at the winning fan ray's landing
point, capped, and then returned to where it started.

Two things play taught that the geometry does not tell you:

- The true angle to the top of a waist-high fence is around sixty degrees down.
  It is correct and it is a stare at your own boots. Hence the cap at 22.
- Driving the view somewhere and then just stopping leaves the player holding a
  camera aimed at the floor with no idea why. Hence the second half of the lock
  returning it, and the exact write-out on release -- easing lands within about
  a degree, and a degree per climb accumulates over an evening.

In the motion branch, read before the end-of-climb test
-------------------------------------------------------

		set fCamOn to player.AuxVarGetFlt "*_Mantle_CamOn" 0

		if fVaultTime <= 0
			PPEndInteraction
			if fCamOn
				set fPitch0 to player.AuxVarGetFlt "*_Mantle_CamPitch0" 0
				player.SetAngle X fPitch0
				EnablePlayerControls 0 0 0 0 1 0 0
				player.AuxVarSetFlt "*_Mantle_CamOn" 0 0
			endif
			return
		endif

After the SetPos Z
------------------

		set fCamLock to player.AuxVarGetFlt "*_Mantle_CamLock" 0
		set fHalf to fCamLock * 0.5
		set fPitch0 to player.AuxVarGetFlt "*_Mantle_CamPitch0" 0

		if fT < fCamLock
			set fCamYaw to player.AuxVarGetFlt "*_Mantle_CamYaw" 0
			set fRate to 9

			if fT < fHalf
				set fTopX to player.AuxVarGetFlt "*_Mantle_Top" 0
				set fTopY to player.AuxVarGetFlt "*_Mantle_Top" 1
				set fTopZ to player.AuxVarGetFlt "*_Mantle_Top" 2

				player.GetPosEx (fCurX) (fCurY) (fCurZ)
				set fPlayerHeight to player.GetObjectDimensions Z
				if fPlayerHeight < 1
					set fPlayerHeight to 128
				endif

				; From the eyes, not the feet, or the angle is wrong by the whole
				; height of the player at the moment it matters most.
				set fEyeZ to fPlayerHeight * 0.85
				set fEyeZ to fCurZ + fEyeZ
				set fLookDist to GetVector3DDistance fTopX fTopY fCurZ fCurX fCurY fCurZ
				if fLookDist < 4
					set fLookDist to 4
				endif
				set fPitchWant to fTopZ - fEyeZ
				set fPitchWant to fATan2 fPitchWant fLookDist

				; Positive GetAngle X looks *down*. The geometric angle is
				; positive upwards, so it is negated going in.
				set fPitchWant to 0 - fPitchWant

				set fPitchMax to player.AuxVarGetFlt "*_Mantle_CamPitchMax" 0
				if fPitchWant > fPitchMax
					set fPitchWant to fPitchMax
				endif
				if fPitchWant < 0 - fPitchMax
					set fPitchWant to 0 - fPitchMax
				endif
			else
				set fPitchWant to fPitch0
				set fRate to 16
			endif

			set fPitch to player.GetAngle X
			set fPitch to fPitchWant - fPitch
			set fPitch to fPitch * fRate
			set fPitch to fPitch * GetSecondsPassed
			set fPitch to player.GetAngle X + fPitch

			player.SetAngle X fPitch
			player.SetAngle Z fCamYaw
		elseif fCamOn
			player.SetAngle X fPitch0
			EnablePlayerControls 0 0 0 0 1 0 0
			player.AuxVarSetFlt "*_Mantle_CamOn" 0 0
		endif
